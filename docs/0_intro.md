# ВСТУП

## Актуальність теми

Автоматизоване опрацювання неструктурованого медіаконтенту (потокових відеотранскриптів, технічної документації, аудіозаписів) для формування персоналізованих навчальних матеріалів вимагає побудови масштабованих конвеєрів обробки природної мови (NLP). За середнього темпу англомовного мовлення 150–180 слів за хвилину транскрипт типової 40–45-хвилинної технічної доповіді або лекції містить орієнтовно 6 000–8 000 слововживань. Використання прямих запитів до комерційних великих мовних моделей (LLM) для наскрізного аналізу таких масивів тексту характеризується високою обчислювальною затримкою: за попередніми розрахунками, послідовна авторегресійна генерація структурованого JSON-виводу обсягом 1 500–2 500 вихідних токенів (для 80–120 відібраних лексичних кандидатів із перекладами, дефініціями та контекстом) за середньої швидкості виводу зовнішніх LLM API 50–80 токенів/с створює затримку орієнтовно 20–50 с, не враховуючи часу обробки вхідного промпту. Крім того, прямі виклики LLM супроводжуються значними витратами токенів, ефектом деградації уваги моделі в середині довгих контекстів (*Lost in the Middle* [1]) та відсутністю збереженого стану знань користувача щодо багатозначних лексичних одиниць (полісемії).

Згідно з корпусно-лінгвістичними дослідженнями лексичного покриття тексту I. S. P. Nation [2] та B. Laufer і G. C. Ravenhorst-Kalovski [3], поріг лексичного покриття (*Lexical Coverage*), необхідний для адекватного розуміння неадаптованого матеріалу в межах моделі засвоєння мови *Comprehensible Input ($i+1$)* S. D. Krashen [4], становить 95–98% відомих слововживань (токенів), тоді як частка цільової нової лексики не перевищує 2–5%. Спираючись на цю теоретичну основу, розробка розподіленої асинхронної системи за архітектурним стилем Modular Monolith із чергами повідомлень (Redis 7 / ARQ) та гібридним конвеєром (`spaCy`, класифікатор System-1 Jev та пакетний генератор System-2 LLM зі Structured Outputs) за попередньою інженерною оцінкою (що підлягає експериментальній верифікації у Розділі 3) дозволяє відсіяти орієнтовно до 90–95% слововживань тексту (службові слова, власні назви та вже відомі користувачеві леми) локально на рівні CPU за мілісекунди до звернення до зовнішніх моделей, забезпечити відмовостійкість (Fault Tolerance) під час пікових навантажень та усунути проблему полісемії на рівні реляційної бази даних PostgreSQL.

## Об’єкт дослідження

Процеси автоматизованого вилучення, багатомовної морфологічної нормалізації та контекстної семантичної дезамбігуації лексичних одиниць із неструктурованих потоків текстових і аудіовізуальних даних в асинхронних розподілених системах.

## Предмет дослідження

Методи, алгоритми та архітектурні патерни побудови гібридного конвеєра обробки природної мови на базі асинхронних черг повідомлень (Redis/ARQ), детермінованого синтаксичного аналізу (`spaCy`), двоконтурної класифікації семантичних значень (Jev та LLM зі Structured Outputs) і математичної моделі оцінки складності контенту (*Comprehensible Input / $i+1$* [4]).

## Мета роботи

Проєктування та програмна реалізація розподіленої системи автоматизованого вилучення, семантичного аналізу та контекстного експорту лексичних одиниць із потокового медіаконтенту для зниження обчислювальної затримки (Latency) і витрат токенів великих мовних моделей та підвищення точності персоналізованого відбору багатозначної лексики.

## Завдання проєкту

Для досягнення поставленої мети у кваліфікаційній роботі необхідно вирішити такі завдання:

1. **Проаналізувати** існуючі програмні аналоги та методи комп'ютерної лінгвістики для автоматизованого вилучення лексичних одиниць, розв'язання проблеми полісемії й кількісної оцінки складності тексту, а також сформувати специфікацію функціональних і нефункціональних вимог згідно з ДСТУ ISO/IEC/IEEE 29148:2018.
2. **Обґрунтувати** вибір архітектурного стилю Modular Monolith із виділеним пулом фонових воркерів і технологічного стеку системи (Python 3.12, FastAPI, PostgreSQL 16, Redis 7, ARQ, `spaCy`, `faster-whisper`, Jev, LLM API) та **спроєктувати** архітектуру програмної системи за нотаціями C4 Model і UML.
3. **Змоделювати** реляційну схему бази даних під керуванням PostgreSQL 16 із розділенням сутностей глобальних лем (`global_lemmas`) та семантичних значень (`lexical_senses`), а також **сконфігурувати** структури оперативного сховища Redis 7 для сесійного кешування й ізольованих черг задач ARQ (`default_queue`, `heavy_transcribe_queue`).
4. **Розробити** алгоритмічне ядро гібридного NLP/AI-конвеєра: модуль оцінки складності матеріалу за моделлю *Comprehensible Input ($i+1$)*, синтаксичний детектор багатослівних одиниць (MWE) на базі `spaCy`, багатофакторну функцію скорингу та двоконтурний модуль семантичної дезамбігуації (Jev та LLM зі Structured Outputs).
5. **Реалізувати** асинхронний REST API шлюз, підсистему інтерактивного тріажу зі зваженою стейт-машиною знань користувача (`KNOWN`, `LEARNING`, `IGNORED`), шар файлових адаптерів експорту (`.apkg`, `.tsv`, `.csv`, `.md`) та конфігурацію контейнеризованого розгортання за допомогою Docker і Docker Compose.
6. **Провести** інструментальний аудит якості програмного коду (Ruff, Mypy), модульне й інтеграційне тестування (Pytest) та навантажувальне стрес-тестування пропускної здатності асинхронних черг (Grafana k6).
7. **Здійснити** науково-практичну апробацію отриманих результатів шляхом підготовки публікації (тез доповіді) та оформлення пояснювальної записки згідно з вимогами ДСТУ 3008:2015 і ДСТУ 8302:2015.
