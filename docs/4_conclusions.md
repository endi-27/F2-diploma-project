# ВИСНОВКИ

> *Статус документа: Шаблон розділу (заповнюється в межах Етапу 7 календарного плану після завершення експериментальної частини).*

У кваліфікаційній роботі бакалавра вирішено актуальне інженерне завдання проєктування та програмної реалізації розподіленої системи автоматизованого вилучення, семантичного аналізу та контекстного експорту лексичних одиниць із потокового медіаконтенту.

Основні науково-практичні та інженерні результати роботи полягають у такому:

1. **Проаналізовано** існуючі програмні аналоги та методи комп'ютерної лінгвістики для автоматизованого вилучення лексичних одиниць, розв'язання проблеми полісемії й кількісної оцінки складності тексту, на основі чого сформовано специфікацію функціональних і нефункціональних вимог за ДСТУ ISO/IEC/IEEE 29148:2018.
2. **Обґрунтовано** вибір архітектурного стилю Modular Monolith із виділеним пулом фонових воркерів і технологічного стеку системи (Python 3.12, FastAPI, PostgreSQL 16, Redis 7, ARQ, `spaCy`, `faster-whisper`, Jev, LLM API) та **спроєктовано** архітектуру програмної системи за нотаціями C4 Model і UML.
3. **Змодельовано** реляційну схему бази даних під керуванням PostgreSQL 16 із розділенням сутностей глобальних лем (`global_lemmas`) та семантичних значень (`lexical_senses`), а також **сконфігуровано** структури оперативного сховища Redis 7 для сесійного кешування й ізольованих черг задач ARQ (`default_queue`, `heavy_transcribe_queue`).
4. **Розроблено** алгоритмічне ядро гібридного NLP/AI-конвеєра: модуль оцінки складності матеріалу за моделлю *Comprehensible Input ($i+1$)*, синтаксичний детектор багатослівних одиниць (MWE) на базі `spaCy`, багатофакторну функцію скорингу та двоконтурний модуль семантичної дезамбігуації (Jev та LLM зі Structured Outputs).
5. **Реалізовано** асинхронний REST API шлюз, підсистему інтерактивного тріажу зі зваженою стейт-машиною знань користувача (`KNOWN`, `LEARNING`, `IGNORED`), шар файлових адаптерів експорту (`.apkg`, `.tsv`, `.csv`, `.md`) та конфігурацію контейнеризованого розгортання за допомогою Docker і Docker Compose.
6. **Проведено** інструментальний аудит якості програмного коду (Ruff, Mypy), модульне й інтеграційне тестування (Pytest) та навантажувальне стрес-тестування пропускної здатності асинхронних черг (Grafana k6).
7. **Здійснено** науково-практичну апробацію отриманих результатів шляхом підготовки публікації (тез доповіді) та оформлення пояснювальної записки згідно з вимогами ДСТУ 3008:2015 і ДСТУ 8302:2015.
